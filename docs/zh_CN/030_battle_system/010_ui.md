## 主体 init

此文件负责绘制战斗框下的内容，以及管理状态中枢。<br>
在 `战斗场景` 中，以 `UI` 作为全局变量在场。

下面是可用方法：

!!! example "UI方法"
    - `UI.SetBarMaxLength(length)` 设置血条的最大长度（像素）。
    - `UI.SetHPBarColor(color)` 设置血条的颜色。
    - `UI.SetMaxHPBarColor(color)` 设置血条**底槽**的颜色（也就是血条后面那条满格背景）。
    - `UI.ToggleKR(bool)` 是否开启 `KR` ，没有动画，如需要可自行编写。
    - `UI.GetKRStarted()` 获取 `KR` 是不是已经开了。
    - `UI.newBounceText(text, pos, color)` 被用于攻击动画中，在攻击动画播放完后，会生成一个伤害数字文本（或 MISS 文本），详情见 [攻击结算](./040_attack.md) 。
        - `text` 要打出的文本，不能用中文。
        - `pos` 在什么位置开始弹跳。
        - `color` 弹跳文本是什么颜色，默认红色 `{1, 0, 0}` 。
    - `UI.newMissText(text, pos, color)` 生成新的不动文本，常见于玩家在校准界面未按下攻击键而漏掉攻击时。
        - `text` 要打出的文本，不能用中文。
        - `pos` 在什么位置开始弹跳。
        - `color` 文本颜色，默认白色 `{1, 1, 1}` ，自带黑色描边。
    - `UI.newMonsterBar(pos, start, target)` 在敌人身上生成一条会补间的怪物血条（攻击结算时用）。
        - `pos` 敌人的位置，血条会画在它的左下方。
        - `start` 起始填充比例（`1` 为满格）。
        - `target` 目标填充比例，会在 30 帧内从 `start` 补间到 `target` 。
    - `UI.SetTextPosition(x, y)` 修改名字开始的一整行文本的坐标。
    - `UI.GetTextPosition()` 返回以名字开始的一整行文本的坐标。
    - `UI.MoveTextPosition(dx, dy)` 以 `(dx, dy)` 的速度移动文本。
    - `UI.SetBarPosition(x, y)` 修改血条的坐标。
    - `UI.GetBarPosition()` 返回血条的坐标。
    - `UI.MoveBarPosition(dx, dy)` 以 `(dx, dy)` 的速度移动血条。
    - `UI.MovePosition(dx, dy)` 同时执行 `Text` 和 `Bar` 的移动函数。
    - `UI.SetHPNameLimit(x)` 修改HP标签的最小横坐标到 `x` ，默认是 `245` 。
    - `UI.GetLayout()` 获取整个布局，需要系统性修改布局时使用此函数。
    - `UI.GetHPBar()` 返回当前血量代表的血条。
    - `UI.GetMaxHPBar()` 返回最大血量代表的血条。
    - `UI.GetKRBar()` 返回KR代表的血条。
    - `UI.GetBars()` 返回如上的三个血条。

**状态中枢与 UI 在主体中被调用，分别对应以下变量：**

`UI.state` & `UI.buttons`

## 按键

仅负责战斗、行动、物品、仁慈四个按键的逻辑。<br>
下面是按键的方法，调用的时候需要写 `UI.buttons.xxx()` ：

!!! example "按键方法"
    - `buttons.GetButtons()` 获取这四个按钮（按顺序）。
    - `buttons.ResetButtons()` 将所有按键归位到待机状态。
    - `buttons.ResetAllState()` 将所有按键归位到待机状态并将玩家放在第一个按钮的位置。
    - `buttons.RemoveButton(id)` 移除第 `id` 个按钮，此按钮将不做任何反馈。
    - `buttons.SetLogic(logic)` 按钮的切换逻辑表，保存的内容为 `起点，终点，操作` 。
    - `buttons.SetSprites(sprs)` 一次性设置四个按钮的图片，详见下文。
    - `buttons.SetAnimations(anims)` 一次性设置四个按钮的图片，详见下文。

### 切换图片

以下为原本的按钮表，元素按按钮顺序依次排开，表内第一项为 `待机图片` ，第二项为 `选中图片` 。

```lua
sprites = {
    {
        "UI/Battle Screen/spr_fightbt_0.png",
        "UI/Battle Screen/spr_fightbt_1.png"
    },
    {
        "UI/Battle Screen/spr_actbt_center_0.png",
        "UI/Battle Screen/spr_actbt_center_1.png"
    },
    {
        "UI/Battle Screen/spr_itembt_0.png",
        "UI/Battle Screen/spr_itembt_1.png"
    },
    {
        "UI/Battle Screen/spr_sparebt_0.png",
        "UI/Battle Screen/spr_sparebt_1.png"
    }
}
```

### 切换动画

与图片不同，动画需要多组数据，即在上述表外再增加一层：

```lua
buttons.animations = (anims or {
    idle = {
        {{
            "poseur.png",
            "bullet.png"
        }, 0.1}
    },
    selecting = {
        {{
            "heart.png",
            "Overworld/spr_exc.png"
        }, 0.1}
    }
})
```

该操作内部调用图片的 `SetAnimation` ，需传入两个值：`图片组` 与 `间隔` 。

## 状态中枢

!!! danger "事先注意"
    本文件通常无需修改，底层逻辑稳定不变， **了解状态流程后即可进入下一页面** 。

### 状态流程

战斗系统使用以下状态标识玩家所处的 UI 阶段：

- `ACTIONSELECT` 玩家回合初始状态（左右选择按钮）。
- `FIGHTMENU` 战斗按键第一页面。
- `ACTMENU` 行动按键第一页面。
- `ITEMMENU` 物品按键第一页面。
- `MERCYMENU` 仁慈按键第一页面。
- `ATTACKING` 战斗按键第二页面，在选择了 `FIGHTMENU` 后再次按下确认进入攻击校准界面。
- `ACTIONMENU` 行动按键第二界面，选择 `ACTMENU` 后确认选择行为。
- `DEFENDING` 敌人回合。
- `DIALOGUERESULT` 行动、物品选择之后会进入此状态等待旁白文本。 <u>注意拼写是 `DIALOGUE` ，不是 `DIALOG` 。</u>
- `TRYINGFLEE` 在按下 `Flee` 后瞬间执行。
- `FLEEING` 按下 `Flee` 成功后持续执行，直到战斗结束，也可切换回 `DEFENDING` 状态。
- `WIN` 战斗胜利。会播放胜利文本、隐藏灵魂，文本播完后淡出并切到结算场景。
