---
title: 🔧 STI 与图块集
---

地图文件由引擎内置的 **STI** （ `Scripts/Libraries/STI/` ）读取。它是通用库，并非为本引擎编写，因此有两条必须遵守的硬约束：违反时不是少绘制部分内容，而是**整个主世界无法加载**。

---

## 硬约束一：图块集必须嵌入地图

STI 载入图块集时有这么一句：

```lua
assert(not tileset.filename, "STI does not support external Tilesets.\nYou need to embed all Tilesets.")
```

也就是说：**图块集不能以外部 `.tsx` 文件的形式存在**，必须嵌进地图里。

| | Tiled 里怎么选 | 导出的 `.lua` |
|---|---|---|
| ✅ 嵌入地图 | 新建图块集时保持默认的 **Embed in map** ；已经是外部的，在图块集面板右键 → **Embed Tileset** | `tilesets` 里**没有** `filename` |
| ❌ 外部图块集 | 新建时勾了 "Save as external tileset file (.tsx)" | 多一行 `filename = "xxx.tsx"` |

!!! warning "违反即触发 assert 崩溃"
    使用外部图块集时， `Map.Init` 里的 `sti(map.current, {"box2d"})` 会直接抛出上面那句英文错误，场景加载中断。<br>
    该错误发生在进入场景的瞬间，容易被误判为地图文件损坏。<br>
    **检查方法**：打开导出的 `.lua` 搜索 `filename` —— `tilesets` 中存在该字段即表示未嵌入。

!!! tip "每张地图各自存一份"
    嵌入是针对**单张地图**的，因此每张 `.lua` 里都会重复一段 `tilesets` 定义。<br>
    该限制是 STI 的硬性要求，无法绕开；结果是导出的 `.lua` 体积增大，图块图片本身不会被复制。

---

## 硬约束二：图块是 20 × 20

UNDERTALE 中每个图块的标准尺寸为 **20 × 20 像素**，新建地图时按该尺寸设置：

| 项 | 值 |
|---|---|
| 地图 Tile Size | `20 x 20` |
| 图块集 Tile Size | `20 x 20` |
| Margin / Spacing | `0 / 0` |

引擎绘制地图时整体放大 **2 倍**，所以：

- 一个图块在 `640 x 480` 的画布上占 **40 × 40** 像素；
- 一屏能看到 **16 × 12** 格；
- 默认的 `30 x 20` 格地图 = 世界坐标 `1200 x 800` 。

!!! warning "填错不会报错"
    引擎**不会**校验该数值。将图块设为 16 或 32 时游戏仍可运行，只是地形与网格不匹配、贴图之间出现缝隙或错位，且不易定位。

!!! example "大件装饰可以例外"
    并非所有图块都必须是 20 × 20。床、钢琴这类整件家具可另建一个**尺寸不同的图块集**（引擎自带的 `Maps/main_scene/main_0.lua` 中就有一个 `50 x 68` 的 `bed` ）。<br>
    但**同一个图块集内部尺寸必须一致**，不要将家具放入地形图块集。

## 图块图片的路径

STI 是这样拼图片路径的：

```lua
utils.format_path(path .. tileset.image)   -- path = 地图 .lua 所在的目录
```

- 路径是**相对于地图 `.lua` 文件**的，不是相对于工程根目录。
- 图片由 `love.image.newImageData()` 直接读盘，**不走** `Sprites` 的资源解析。

由此得到三条：

!!! warning "不要将 .lua 导出到其他目录"
    `.tmx` 和导出的 `.lua` 要放在**同一目录**（或相对深度一致）。<br>
    换目录导出会让 Tiled 写进去的相对路径失效，表现是地图全空但没有任何报错。

!!! warning "Game 区覆盖地图时，图块图不会被一起覆盖"
    `Game/Maps/xxx.lua` 能覆盖 `Maps/xxx.lua` ，但里面的 `image` 仍然按 `Game/Maps/` 这一侧去找。<br>
    所以在 Game 区放一份地图的同时，也得把它的图块图片按同样的相对路径复制一份过去。

!!! warning "文件名大小写敏感"
    图块图片路径**大小写敏感**：Windows 上可正常运行，打包到 Android / Linux 后整张地图会变白。<br>
    路径只使用 ASCII，不使用中文目录名。

## 动画图块

UNDERTALE 的水面、火把、瀑布都是动画图块。在 Tiled 里做动画图块：

1. 在 **Tilesets（图块集）** 面板**双击**图块集，打开图块集编辑器（只在地图里选中是不够的）。
2. 选中作为动画宿主的那一格：地图上绘制的就是这一格。
3. 打开动画编辑器：菜单 `Tile` → `Animation` （不同版本可能挂在 `Tileset` 菜单下，中文界面为「图块 → 动画」），或点图块集编辑器工具栏上的胶片图标；图块集视图**下方**会展开一条时间轴。
4. 把每一帧从图块集里**拖进**时间轴，拖动可调整顺序。
5. 时间轴上每帧下方是这一帧的**持续时间（毫秒）**，可以直接点开编辑。Tiled 会循环预览。
6. 导出 `.lua` 。

导出后，那个格子在 `tiles` 里会多出一段：

```lua
tiles = {
  {
    id = 12,
    animation = {
      { duration = 150, tileid = 12 },
      { duration = 150, tileid = 13 },
      { duration = 150, tileid = 14 },
    }
  }
}
```

引擎侧无需额外处理 —— `map.lua` 的 `Map.Update` 里已调用 `map._map:update(dt)` ，STI 会自行累加时间、切换帧、把新帧的 quad 写回 sprite batch。

??? example "STI 的推进逻辑（ `STI/init.lua` 的 `Map:update` ）"
    ```lua
    tile.time = tile.time + dt * 1000          -- dt 是秒，乘 1000 换成毫秒
    while tile.time > tonumber(tile.animation[tile.frame].duration) do
        tile.time  = tile.time - duration
        tile.frame = tile.frame + 1
        if tile.frame > #tile.animation then tile.frame = 1 end
    end
    -- 翻帧后：把新帧的 quad 写回所有实例所在的 sprite batch
    local t = self.tiles[tile.animation[tile.frame].tileid + self.tilesets[tile.tileset].firstgid]
    j.batch:set(j.id, t.quad, j.x, j.y, j.r, tile.sx, tile.sy, 0, j.oy)
    ```

### 动画图块的四个注意事项

!!! warning "时长单位是毫秒"
    时间轴上填的 `150` 是 **150 毫秒**，不是 0.15 秒，也不是 150 帧。若需要一格停留 0.5 秒，填 `500` 。

!!! warning "动画帧必须来自同一个图块集"
    STI 用 `tileid + firstgid` 换算帧的 gid，而这个 `firstgid` 取自**宿主格所在的图块集**。<br>
    跨图块集引用会取到不相关的格子：不会报错，只会绘制出错误的图案。

!!! warning "所有实例永远同相位"
    STI 是按**图块（gid）**推进动画的，不是按"地图上放的每个实例"。<br>
    因此同一张地图中所有相同的动画图块会**同时播放**，无法实现水流、火焰错开相位的效果。<br>
    如需错开相位，复制帧并创建第二个动画图块，再手动错开摆放。

!!! tip "没用到的动画不耗性能"
    `Map:update` 只在 `self.tileInstances[tile.gid]` 存在时才刷新 batch，也就是只有**真的画在地图上**的图块才会走这段。<br>
    定义了但没摆上去的动画不会拖慢帧率。

!!! note "动画只是视觉"
    动画图块**不参与碰撞**，也不产生任何运行时对象 —— 碰撞完全由对象层决定，见 [地图与对象层](./010_map.md) 。

## 会影响整张地图的问题：泄漏的 `setColor`

STI 画瓦片用的是 `Map.drawLayer` 里的 `lg.setColor(r, g, b, a * layer.opacity)` —— 也就是说，**它用的是当时环境里的颜色**。

而 LÖVE 默认的 `love.run` **不会在每帧之间重置绘图状态**（只调 `origin()` 和 `clear()` ）。于是：

> 在某一帧调用 `setColor` 后未还原，该颜色会**跨帧泄漏**，成为下一帧的环境色，使**整张地图**被染上该颜色或透明度。

引擎中已修复过一处该问题，位于虚拟键盘：

```lua
-- Scripts/Libraries/Controller/VirtualKeyboard.lua  Draw() 末尾
-- The default love.run does NOT reset the graphics state between frames (it only
-- calls origin() + clear()). The colour left behind here therefore became the
-- ambient colour of the NEXT frame -- and STI paints the tilemap with that
-- ambient colour ... so a leaked tint made every map tile render translucent
-- (once into STI's own map canvas, once again when that canvas is blitted back).
SE.graphics.setColor(1, 1, 1, 1)
```

!!! warning "自定义 HUD / 对话框时的处理方式"
    规则如下：**所有自行调用 `setColor` 的位置，绘制结束后将颜色还原为 `(1, 1, 1, 1)` 。**<br>
    未还原时表现为地图突然半透明或变色，与相关代码无明显关联，不易定位。字体同理：帧末也需要还原 `setFont` 。
