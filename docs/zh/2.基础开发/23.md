# 节拍器（Beat）

`Scripts/Libraries/Beat.lua` 提供了一个简单的节拍事件处理器。

如果需要精确节拍同步——例如，制作音乐驱动的游戏、或者只是单纯的踩点/音频可视化……

那这个库就是为你而准备的。

---

## 主要模块与方法

### 配置设置

- `SetBPM(new_bpm)`：设置BPM值（需为正数）。
- `SetCycleLength(length)`：设置节拍循环长度（如4拍一小节）。

### 状态获取

- `GetBeat()`：返回当前节拍的整数部分和小数部分。
- `GetBar()`：返回当前小节号和节拍在循环中的位置。

所有返回值都是从 1 开始计数的。

### 事件处理

- `RegisterEvent(event_type, handler)`：注册事件回调（支持beat（节拍触发）和reset（重置）事件）。

### 节拍控制

- `SetBeat(beat)`：直接设置当前节拍（触发重置事件）。
- `Reset()`：重置节拍到0（保留BPM设置）。

### 状态更新

- `Update(d)`：基于时间增量（dt）更新节拍状态，
- `UpdateFromTime(time)`：基于音乐时间更新节拍状态。

它们都会自动触发节拍事件和循环检测。

### 条件检测

- `OnBeat(target_beat)`：检查是否到达目标节拍（支持循环内的相对节拍检测）。

## 示例

`Scripts/Scenes/TestPlace` 下有两个示例场景：`scene_beat.lua` 和 `scene_beat_from_time.lua`。

其整体结构基本一致，只不过前者使用 `Update(dt)` 更新节拍，而后者使用 `UpdateFromTime(time)`。

首先，我们需要导入这个库——当然，这往往需要配合一段 [音频](./7.md)。

```lua
-- 我们在这里导入了音频
local mus, ins = audio.PlayMusic("mus_options_winter.ogg", 1.0, true)

-- 然后在这儿导入了节拍库
local beat = require("Scripts.Libraries.Beat")
```

然后，我们需要初始化节拍器——毕竟它还不知道你的音乐的 BPM 是多少，也还没有注册任何回调。

```lua
function setupBasicBeatTracking()
    -- 设置 BPM
    beat.SetBPM(140)

    -- 在这里注册 "beat" 回调。它会在每一拍，触发 function(current_breat)
    -- 我们在这里实现了一个简单的节拍器！
    beat.RegisterEvent("beat", function(current_beat)
        local beat_sound = current_beat % 4 == 1 and "metronome_high.wav" or "metronome_low.wav"
        audio.PlaySound("Beats/" .. beat_sound, 1.0, false)
        print(string.format("Triggered on the %d beat!", current_beat))
    end)

    -- 在这里注册 "reset" 回调。它会在节拍器被 Reset() 时触发。
    beat.RegisterEvent("reset", function(beat)
        print(string.format("Beat reset to: %.2f", beat))
    end)
end

-- 当然，声明完这个方法后你就可以，并且也应该调用它了。
setupBasicBeatTracking()
```

但仅仅这样的话，节拍器是无法工作的。因为它内部记录的时间压根没有被更新。

我们需要在 update 中，将节拍器更新。这里有两个选择——这也是两个文件的唯一不同之处。

---

选项A：直接传入 dt。

```lua
function SCENE.update(dt)
    beat.Update(dt)

end
```

如果这么做，节拍器会和游戏update(dt)的时间同步。这适用于简单场景。

但是，音频如果非常长——或者你需要严格的对齐音频，不希望音乐和节拍器产生不同步的现象的话，你就应该使用——

选项B：用音乐时间驱动。

```lua
function SCENE.update(dt)
    beat.UpdateFromTime(mus:tell())
end
```

`mus:tell()` 会获取到音乐当前的播放时间。这会保证节拍器是跟随音频一起步进的——即便音频由于某种奇奇怪怪的原因发生卡顿。

## 其他参考

这里还有一些示例可供查看。

但请注意，这里的代码示例仅作为参考，具体实现需要相对应在框架内进行调整。

```lua
-- 导入节拍管理库
local Beat = require("Beat.lua")

-- 示例1：基础节拍跟踪与事件触发
function setupBasicBeatTracking()
    -- 设置BPM为120（常见流行音乐速度）
    Beat.SetBPM(120)

    -- 注册节拍事件：每整数拍触发
    Beat.RegisterEvent("beat", function(current_beat)
        print(string.format("第 %d 拍触发！", current_beat))
    end)

    -- 注册循环重置事件
    Beat.RegisterEvent("reset", function(beat)
        print(string.format("节拍重置至：%.2f", beat))
    end)
end

-- 示例2：游戏中的节拍同步逻辑
function gameBeatExample()
    Beat.SetBPM(140)  -- 设置较快节奏
    Beat.SetCycleLength(4)  -- 4拍一个循环

    -- 模拟游戏更新循环（dt为帧时间差）
    function gameUpdate(dt)
        Beat.Update(dt)  -- 更新节拍状态

        -- 检测特定节拍点（如每小节第1拍）
        if Beat.OnBeat(0) then
            spawnEnemy()  -- 在强拍生成敌人
        end

        -- 检测循环内的第3拍
        if Beat.OnBeat(2) then
            triggerSpecialEffect()  -- 触发特效
        end

        -- 实时获取节拍信息用于UI显示
        local integer_beat, fractional_beat = Beat.GetBeat()
        updateBeatUI(integer_beat, fractional_beat)
    end
end

-- 示例3：音乐可视化应用
function audioVisualizationExample()
    Beat.SetBPM(90)
    Beat.SetCycleLength(8)  -- 8拍一个乐句

    function onAudioFrame(dt)
        Beat.Update(dt)

        local current_bar, bar_beat = Beat.GetBar()

        -- 根据小节位置调整可视化强度
        if bar_beat < 2 then
            setVisualizerIntensity(0.5)  -- 弱拍阶段
        else
            setVisualizerIntensity(1.0)  -- 强拍阶段
        end

        -- 每小节第一拍突出显示
        if Beat.OnBeat(0) then
            triggerBarHighlight()
        end
    end
end

-- 示例4：手动节拍控制（用于调试或特殊场景）
function manualControlDemo()
    -- 直接跳转到特定节拍
    Beat.SetBeat(16.5)  -- 跳到第16.5拍

    -- 重置整个节拍系统
    Beat.Reset()
end

-- 运行示例
setupBasicBeatTracking()

-- 模拟时间流逝（每帧调用）
for i = 1, 100 do
    Beat.Update(1/60)  -- 假设60帧每秒
end
```
