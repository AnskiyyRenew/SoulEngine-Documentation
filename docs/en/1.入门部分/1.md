# Getting Started Guide

Welcome to the **LÖVE - SoulEngine** documentation.<br>
Here you will learn everything about this engine template.<br>

---

## Preface

I will not tell you to play [UNDERTALE](https://undertale.com/) first, because if you are here for **development**, we can **skip that step**.<br>
If you want to know what UNDERTALE looks like, watch some videos online; this guide does not cover the game itself.<br>

If you are seeing this **documentation** before the **engine**, you probably do not know how to download and use it.<br>
Next, we will start from scratch with installation and downloading so you can run it successfully.<br><br>
***Note: No matter which platform you use for development, your environment should support the corresponding version of the LOVE2D framework.***

---

## Installation

You need to install the [LÖVE (LOVE2D)](https://love2d.org) engine.<br>
This document was written at the end of 2025, and LOVE-12.0 had not been released yet.<br>
**So we download the latest available version, which is LOVE-11.5.** to prepare for our development.<br><br>
*Note: Always pay attention to the latest SoulEngine version number. If the version number is beyond 3.0.0, that means the project has entered the LOVE-12.0 era. In that case, ignore the previous instruction and download LOVE-12.0.*<br>

After that, download the [SoulEngine](https://github.com/AnskiyyRenew/love2d-undertale-template/releases/) engine.

**After completing the two steps above, we will start configuring the coding environment.**

### Desktop setup

First, choose a code editor you like.<br>
For desktop development, I recommend [Visual Studio Code](https://vscode.dev).<br><br>
After installation, unzip the SoulEngine archive.<br>
Then go into the extracted folder and open that location with **VSCode**.<br><br>

- Method 1: right-click the extracted folder and choose Open with Code<br>![Image did not display correctly](../img/s1-download/PC-1.png)
- Method 2: open a terminal in the extracted folder and enter `code .`<br>![Image did not display correctly](../img/s1-download/PC-2.png)

<br>
After opening with **Code**, you should see a lot of items on the left, which means it worked.<br>
But do not hurry yet, because our setup is not complete and testing the game will still be difficult.<br>
Next, to make testing more convenient, we need to install an **extension**.<br><br>
First, you can see a small square icon on the left:<br>![Image did not display correctly](../img/s1-download/PC-3.png)<br>
Then search for `love2d` in the top search box to filter extensions that include love2d.<br>
Install the one you prefer, but it is best to choose one that can launch the game quickly.<br>

From the above, I recommend this extension:<br>![Image did not display correctly](../img/s1-download/PC-4.png)<br>
This is simply a launcher extension and does not interfere with how you write code, which is why I recommend it.<br><br>
Next, you need to configure this extension so it works correctly.<br>

First open Settings using the gear icon in the lower-left corner. Then you will see `Settings`.<br>![Image did not display correctly](../img/s1-download/PC-5.png)<br><br>
Then type `love` in the top search box so you can quickly locate the LOVE2D settings.<br>![Image did not display correctly](../img/s1-download/PC-6.png)<br>
**Make sure the path is set exactly to the appropriate love.exe program, otherwise the game will not run successfully.**<br><br>
After this step, press `Alt + L` to test whether the game opens. If a window appears, then the extension setup is **complete**.<br><br>

**Some additional notes**<br>

Indeed, on `Linux`, there is a better way to launch the game: use the command terminal.<br>
Open a terminal in the project folder and run `love .` to start the game with LOVE2D.

## Version number explanation

---

You may have already noticed that `SoulEngine` version numbers follow a specific pattern. Here we explain what each part means.<br>

We use the most complete format: <br>`a.b.c-d`<br>

- `a`<br>stands for the major version. When this number increases, it means the engine has made a **major change**, such as **API modifications** or a large structural rewrite. **Older projects may require significant changes or a complete rewrite to run on this version.**
- `b`<br>stands for the minor version. When this number increases, it means serious bug fixes or important updates were made. In short, it indicates a larger update than the previous version. **Usually old projects only need a few small modifications to continue running.**
- `c`<br>stands for the patch version. When this number increases, it means small bug fixes or optimizations were made. **Generally old projects do not need changes and can run by replacing files.**
- `-`<br>is a separator and has no real meaning.
- `d`<br>is an extra label. If the version is stable, `d` is `stable`; if the version is not yet confirmed stable, `d` can be `alpha`, `beta`, `nightly`, or `lazy`.

<br>
**Note: Version numbers may also include time-based values down to the hour. If so, compare the version strings carefully.**<br>

For example: `2025.5.1-15-beta`
