## Essential knowledge to master

### 1. Lua language

The language used by the LOVE2D engine is `Lua`.<br>
This is like learning vocabulary before you can read an English book.<br>

Lua has a similar relationship to LOVE2D.<br>

The best place to learn Lua is the official Lua [website](https://lua.org), but if you want to develop quickly, you probably do not have time to learn everything fully.<br>

For that reason, we choose to **learn by doing**. Building while learning is the most efficient method.<br>

Of course, if you want to learn the most basic concepts quickly, click [this Lua tutorial](../Lua教程速通/1.md). It will take you through the fundamentals quickly.<br>

### 2. LOVE engine

First, we need to explain what a `LOVE2D` game project can look like.<br>

A LOVE2D game project is usually very lightweight, but the structure should be clear. The smallest runnable project only needs a `main.lua` file, and LOVE will execute the callbacks defined there. Common points:

- Required files
    - `main.lua`: the program entry point, with common callbacks such as `love.load`, `love.update(dt)`, `love.draw`, `love.keypressed`, etc.
    - `conf.lua` (optional): used to configure window size, title, scaling, and startup parameters.
- Typical directory layout (example)
```text
mygame/
├─ main.lua
├─ conf.lua
├─ src/             # game logic modules
│  ├─ game.lua
│  └─ player.lua
├─ assets/
│  ├─ images/
│  └─ sounds/
└─ libs/            # third-party libraries (such as hump, push, etc.)
```
- Code organization recommendations
    - Split different features into modules (`require "src.game"`) to avoid putting all logic into `main.lua`.
    - Use a resource manager to load/cache images and audio, avoiding repeated loads.
    - Use game states or a scene manager to switch between menu/game/pause logic.
- Callbacks and frame loop
    - `love.load()`: initialize resources and state.
    - `love.update(dt)`: update game state each frame, using the passed `dt` to keep behavior framerate-independent.
    - `love.draw()`: render the current state (keep rendering separate from logic).
- Input and files
    - Common callbacks: `love.keypressed`, `love.mousepressed`, `love.textinput`.
    - `love.filesystem` is used to read/save user data and handle cross-platform paths.
- Packaging and running
    - During development, run the project folder directly with `love.exe` or the `love` command.
    - For release, package the project folder as `.zip` and rename it to `.love`, or bundle it with a platform executable.
- Tips
    - Keep the structure simple early in development, then refactor into modules as the project grows.
    - Build a runnable minimum viable product (MVP) first, then gradually add features.
    - Put commonly used third-party libraries in `libs/` and require them for easier management and upgrades.

The above content can serve as an introductory engineering guideline to help organize a LOVE2D project from scratch into a maintainable structure.

### 3. SoulEngine engine

The content above introduces the most basic LOVE2D game project, but since you are here, you are using `SoulEngine` for development.<br><br>
The project structure is not exactly the same, so we explain it below:<br>

```txt
SoulEngine/
├─ main.lua             # main program file
├─ conf.lua             # configuration file (remember to modify it before release)
│
├─ Localization/        # localization folder
│  ├─ en.lua            # English translation data file
│  ├─ zh_CN.lua         # Simplified Chinese translation data file
│  └─ LOCALIZE.lua      # localization library file, contains localization functions
│
├─ Maps/                # Overworld map folder containing all Overworld map data
│  ├─ images/           # stores map tile images and other assets
│  ├─ tmx/              # stores Tiled project files for editing
│  ├─ tsx/              # stores tile set definitions for images
│  └─ ruins_x.lua       # example Overworld Lua data files
│
├─ Scripts/             # game logic modules
│  ├─ Libraries/        # Lua libraries used by the project
│  ├─ Scenes/           # separate scene files
│  ├─ Shaders/          # shader files written in GLSL
│  └─ Waves/            # round sequence files used in scene_battle.lua
│
└─ Resources/           # all resource assets
   ├─ Fonts/            # font files
   ├─ Libs/             # extension libraries, including dlls and external libraries
   ├─ Music/            # music files
   ├─ Sounds/            # sound effect files
   └─ Sprites/          # sprite files
```

**After understanding the directory layout, we can officially move into the development phase.**
