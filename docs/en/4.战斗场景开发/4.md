# Custom Attack Effects

Maybe you are tired of the common stick and knife attacks. No problem: SoulEngine supports custom attack styles, and all attack effects are created by you.

---

## Attack File Location

As mentioned before, a battle can customize its attack style. Those attack files are located in `Scripts/Libraries/Battle/Patterns/`.

There are three files inside:
- `doubleatk`: used for double-attack effects.
- `stick`: the classic stick/knife attack.
- `template`: the base template used for copying and modifying.

---

## Attack Execution Order

Next, let's explain the underlying logic order of an attack so you can better understand how the system works.

**First**, the player enters the `ATTACKING` state. This state triggers the first attack library function, `Create()`. Here you initialize the battle UI, such as creating an aim target and a moving bar for the original style, or creating a six-shot cylinder for a Clover-style weapon.

**Second**, after creation, all logic is handled by the `Update` function. This includes when the bar moves, how it moves, when it stops, how damage is calculated, or whether the player can press confirm multiple times. The attack logic is fully controlled by your `Update` code.

**Finally**, the total damage is calculated and passed to `finalHurt`, which handles the rest of the battle resolution.

Here is the full process:

| STATE | Attack Animation | Behavior Description |
|-------|------------------|----------------------|
| Entering ATTACKING | Call `Create` | Initialize all attack UI and conditions |
| ATTACKING | Continuously call `Update` | Custom attack style updates continuously |
| ~ATTACKING (not well defined, usually ATTACKING) | `BattleInit` waits for `_end` to finish the attack and calculates damage | The battle system waits for `_end` to be set to `true`, then advances the flow |
| ~(any state except ATTACKING) | Call `Reset` | Reset all attack parameters and variables for the next attack |

***In short, you only need to modify these three parts to create a custom attack animation and effect.***

---

## Creating an Attack Animation

After the above explanation, you should have a general idea of the logic. Now let's write a custom attack animation.

### Underlying Variables

**These variables are mandatory and must be set, because the lower-level system depends on them having definite values.**

- `enemy`: every attack animation needs this enemy object to get enemy information, such as the target position.
- `_end`: if set to `true`, the lower-level system will immediately process the attack result. Only set this to `true` after the attack truly ends. For example, in a stick/knife attack, set it after the player presses confirm and the bar stops.
- `finalHurt`: set this before `_end`. If you want the attack to miss, set a negative value.

All other variables are user-defined (refer to the `template` file for examples).

---

## Understanding the Default Attack Template

You may want to know what the default template does before copying it. Let's break it down.

First, ignore the content before `Create` and only read the `Create` function:
```lua
function template.Create()
    template._has_sliced = false
    template.finalHurt = 0
    template.Elements = {}

    -- target (example)
    local target = sprites.CreateSprite("UI/Battle Screen/spr_target_0.png", 12)
    target.y = 320
    target:MoveTo(320, target.y)
    table.insert(template.Elements, target)

    -- moving bar (example)
    local bar = sprites.CreateSprite("UI/Battle Screen/Player Attack/spr_targetchoice_0.png", 16)
    bar.y = 320
    bar:SetAnimation({
        "UI/Battle Screen/Player Attack/spr_targetchoice_1.png",
        "UI/Battle Screen/Player Attack/spr_targetchoice_0.png"
    }, 5)
    -- randomly begin from left or right to stay compatible with the original logic
    local pos = math.random(1, 2)
    if pos == 1 then
        bar.x = 320 + 280
        bar.velocity.x = -6
        bar.newPosvar = 2
    else
        bar.x = 320 - 280
        bar.velocity.x = 6
        bar.newPosvar = 1
    end
    table.insert(template.Elements, bar)
end
```
**Explanation:**

It instantly creates a target, which is the aiming area, and then creates a bar, which is the moving attack bar.

When the bar is created, the `pos` variable randomly chooses the start direction. If `pos == 1`, the bar moves in from the right; otherwise, it moves in from the left.

*These two sprites are then inserted into `template.Elements` so `Update` can control them later.*

Now let's look at `Update`:
```lua
function template.Update(dt)
    -- If there is no enemy (extreme case), return immediately.
    if not template.enemy then return end

    -- If the player presses confirm (this example uses keyboard.GetState, consistent with Battle)
    if keyboard.GetState("confirm") == 1 and not template._has_sliced then
        template._has_sliced = true
        template._end = true
        print("ATTACKED BY LIBRARY")

        -- play sound and create the slice effect at the enemy's position
        audio.PlaySound("snd_slice.wav")
        local slice = sprites.CreateSprite("UI/Battle Screen/Player Attack/spr_slice_o_0.png", 18)
        slice:SetAnimation({
            "UI/Battle Screen/Player Attack/spr_slice_o_1.png",
            "UI/Battle Screen/Player Attack/spr_slice_o_2.png",
            "UI/Battle Screen/Player Attack/spr_slice_o_3.png",
            "UI/Battle Screen/Player Attack/spr_slice_o_4.png",
            "UI/Battle Screen/Player Attack/spr_slice_o_5.png"
        }, 10, "oneshot-empty")

        -- use the enemy's current position
        local e = template.enemy
        if e and e.position then
            slice:MoveTo(e.position.x, e.position.y)
        else
            slice:MoveTo(320, 320) -- fallback to center to avoid crashes
        end
        table.insert(template.Elements, slice)

        -- calculate damage (example: based on distance between bar and target)
        local damage = template.GetMaxDamage() or 0
        local tar = template.Elements[1]
        local bar = template.Elements[2]
        bar.velocity.x = 0  -- stop the bar
        if tar and bar and bar.x and tar.x then
            local absLength = math.abs(bar.x - tar.x)
            if absLength > 5 then
                damage = math.ceil(damage * 0.9 * (1 - absLength / 280))
            end
        end

        -- write the final damage back to the pattern. Battle uses this during resolution.
        template.finalHurt = damage
    end

    -- check if the bar went out of bounds; if so, treat it as a miss and set 0 damage.
    local bar = template.Elements[2]
    if bar and (bar.x < 40 or bar.x > 600) and not template._has_sliced then
        template._has_sliced = true
        template._end = true
        template.finalHurt = -999
        bar.velocity.x = 0
    end
end
```
**Explanation:**

If the player presses attack and this is the first press (controlled by `_has_sliced`), the code creates a slice effect and sets `_end = true`. This tells the battle system that the attack is complete, the player can no longer act, and the system should resolve the attack.

It uses the enemy's position to place the attack effect at the enemy.

Then it stops the bar, calculates the damage based on the bar's position, and stores the result in `template.finalHurt`, which the battle system uses.

Finally, it handles the case where the player never attacks by checking whether the bar leaves the screen. In that case, it sets `_end = true` and the attack ends with a miss.
