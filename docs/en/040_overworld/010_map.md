title: 🔧 Maps and Object Layers
---

Maps are edited in **Tiled**, exported to `.lua` and placed in `Maps/`. The engine reads them with the built-in `STI` library and translates object layers into collision bodies.

Path: `Maps/` (engine default), `Game/Maps/` (Game area, same-name override). <br>
Module path: `Scripts/Libraries/Overworld/map.lua`, exposed as the global `Map`.

---

## Basic Map Parameters

The engine's built-in maps all use these parameters; copy them when creating a new map:

| Item | Value |
|---|---|
| Orientation | `orthogonal` |
| Tile size | `20 x 20` |
| Map size | `30 x 20` (changeable) |
| Export format | `.lua` |

The exported `.lua` goes under `Maps/` (or `Maps/subdir/`). Keeping the Tiled project and `.tmx` in `Maps/tmx/` is just a convention for easily finding and editing them later.

!!! tip "Two more hard constraints on tilesets"
    **Tilesets must be "embedded in the map" (no external `.tsx`),** otherwise STI will directly assert and crash the scene; **tile size must be 20 × 20**. <br>
    The tricks around tile image paths and animated tiles are all covered in **[STI and Tilesets](./015_sti.md)**.

## Object Layers

**The name of an object layer determines how it is processed.** A misspelled name (or a Chinese name) will cause the entire layer to be ignored.

| Layer name | Purpose | Common properties |
|---|---|---|
| `marks` | Spawn point / teleport landing | `id`, `direction` |
| `walls` | Walls (solid collision) | `id` (optional) |
| `warps` | Teleport region (switch scene on contact) | `id` |
| `triggers` | Custom trigger region | `id` + any custom property |
| `signs` | Sign | `id` (optional) |
| `saves` | Save point | `id`, `room`, `x`, `y` |
| `chests` | Chest | `id`, `give` |

These layers fall into three categories, processed **differently**:

| Category | Layer | Physics body | Can the player walk through? |
|---|---|---|---|
| Pure data | `marks` | none | Yes (no collision involved) |
| Solid | `walls` | `static` rectangle / polygon / ellipse | **No**, truly blocks the way |
| Sensor | `warps`, `triggers` | `kinematic` + `setSensor(true)` | Yes, walking in records it into the interaction list |
| Blocking interactive | `signs`, `saves`, `chests` | `kinematic` (**not** a sensor) | **No**, but contact still records it into the interaction list |

In other words, only `warps` and `triggers` are "passable regions"; signs, save points, and chests block you just like real walls — you must **get up against them** to trigger them. These three internally use the same contact event (`beginContact`), except the collision shape is taken as a narrow strip at the bottom of the sprite.

!!! warning "`marks` has no physics body"
    `marks` is only read as a coordinate point `{x, y, direction}`, generating no collision body and no sprite. So it can be placed inside a wall, or used as a pure logic anchor.

!!! warning "Coordinates must be multiplied by 2"
    When reading objects, the engine multiplies `x` / `y` / `width` / `height` by `2` before building collision bodies. <br>
    So the coordinates obtained at runtime are already world coordinates, but **the numbers you see in Tiled are pre-scale**.

---

### marks spawn point

Determines where the player stands when entering this map. `id` is its number, `direction` is the facing upon entry.

- Nothing specified → use the first mark.
- `DATA.marker` has a value → use the mark matched by `id` (written by `Overworld.ChangeScene` when switching scenes).
- `DATA.savedpos` is true → use the `DATA.position` save position (load / return from Battle).

!!! tip "Returning from Battle relies on savedpos"
    When an encounter triggers, the engine automatically sets `DATA.savedpos` to `true` and records the current position, so after the fight the player returns to the original spot instead of the spawn point.

---

### walls

`walls` is the only thing that truly blocks the player. All three shapes are supported:

- Rectangle (default)
- Polygon — diagonal walls, sharp corners, anything
- Ellipse / circle — uses the smaller of `width` or `height` as the diameter

The `rotation` property is applied correctly (both polygons and ellipses rotate along).

!!! example "Wall friction"
    Both wall and player friction are `0.01` — deliberately low: with low friction, the player slides **along the wall** when hitting a diagonal wall instead of sticking to it. <br>
    The two values are in `wall_friction` in `map.lua` and in `char.lua` respectively; setting them to large numbers makes the player "stick to walls".

---

### warps teleport region

A region that switches scene on contact. It only **tells you that contact happened**; the scene-switching action is written by you in the scene script (see [Interaction and Dialogue](./030_interact.md)).

### triggers custom trigger region

Like `warps`, this is a sensor, but with no fixed purpose — add any properties you like. The most common usage is to add a custom property (e.g. `rr`) as a "room number" and branch on it.

```lua
if (Overworld.getInteractResult("trigger", 1, "rr")) then
    -- touched a trigger region where rr == 1
end
```

### signs / saves / chests

The engine automatically generates sprites for these three (sign, save point, chest) — no need to draw them yourself. Properties:

- `signs` — if `id` is left blank, auto-numbered by placement order.
- `saves` — `room` is the place name shown at the save point, `x` / `y` are the save coordinates.
- `chests` — `give` is read verbatim into the runtime object's `give` field (blank = `false`), but **nothing in the engine reads it**. What a chest actually gives is decided by `CHEST` (= `DATA.chests`) and your scene script. See [Menu · Save · Chest](./040_menu.md).

## Runtime Access

All objects are collected into `Map.objects`, tabulated by type:

!!! example "Object containers"
    - `Map.objects.marks` / `.walls` / `.warps` / `.triggers` / `.signs` / `.saves` / `.chests` are the runtime object lists for each type.
    - `Map.objects.unknowns` holds object layers whose name didn't match. **This table is currently always empty** — the engine only dispatches by known layer names, and silently skips unrecognized layers rather than writing to here. Spotting a typo requires `Map.debug_objects` (see below).
    - `Map.debug_objects` the raw Tiled objects, indexed by **layer name** (including misspelled layers), for debug drawing only.

!!! tip "How to find a misspelled layer name"
    With `Overworld.debug` on, **all** object layers in `Map.debug_objects` are drawn, including the misspelled one. <br>
    If its name isn't in the color table, it falls into `unknowns`' **dark red** — a patch of dark red boxes means this layer's name wasn't recognized by the engine. See "Debug" at the end of this page.

Each runtime object roughly looks like this:

```lua
{
    x, y,               -- world coordinates (already ×2)
    width, height,      -- size (already ×2)
    id,                 -- the id in properties
    properties,         -- all properties filled in for this object in Tiled
    body, fixture,      -- physics body (present for walls / warps / triggers / signs / saves / chests)
    sprite,             -- sprite (present for signs / saves / chests)
}
```

If you don't want to touch collision and just want to fetch an object by condition, `Overworld.FindObject` is more convenient. See [Interaction and Dialogue](./030_interact.md).

## Map and Physics World

!!! example "Map methods"
    - `Map.Init(lua_file)` loads the map. Skips and prints a hint if already initialized.
    - `Map.Update(dt)` advances tile animation, the physics world, the player, and the camera. Called automatically by the engine.
    - `Map.Destroy()` destroys all collision bodies and sprites.
    - `Map.current` the actual path of the current map file (may be the Game-area copy).
    - `Map.char` the player module.
    - `Map.world` the physics world.

!!! example "World methods"
    - `World.Init()` builds the physics world and registers collision callbacks. Repeated calls are ignored.
    - `World.Update(dt)` advances the physics world.
    - `World.Destroy()` destroys the physics world and all bodies within it.
    - `World.interactions` interaction state (see [Interaction and Dialogue](./030_interact.md)).

!!! warning "Tile animation needs Update"
    Tiled's animated tiles only advance when `Map.Update` calls `map:update(dt)`. <br>
    This line is already written by the engine — don't delete it while optimizing.

## Camera

`Overworld.Init` scans all visible tile layers, computes the **rectangle that actually has content** (accounting for layer offsets and the negative-coordinate regions of infinite maps), then converts it into `Camera:setBounds` based on the viewport size.

When the coverage is smaller than the viewport, the camera is locked at the center.

To take manual control:

```lua
ow.Init("Maps/main_scene/sol.lua")
Camera:setBounds(min_x, min_y, max_x, max_y)   -- override the automatic result
Camera:setPosition(x, y)                        -- manual positioning
Overworld.follow_player = false                 -- turn off auto-follow
```

## Debug

```lua
Overworld.debug = true
```

Once enabled:

- All object layers' collision bodies are drawn, colored by type (`walls` red, `triggers` green, `warps` magenta, `saves` yellow, `chests` orange, `signs` purple, `marks` cyan).
- Press **Space** to teleport the camera to the mouse position.
